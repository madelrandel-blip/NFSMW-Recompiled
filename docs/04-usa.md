# USA (NTSC) support

This fork adds support for the **NTSC/USA** version of Need for Speed: Most Wanted
(2005) for Xbox 360, alongside the original PAL Spain target. The work follows the
methodology of the Spanish project: the recompiler itself is region-agnostic; what
changes per region is a small set of hand-written configuration.

## What the USA XEX looks like

| | PAL Spain | NTSC/USA |
|---|---|---|
| Title ID | `454107D9` | `454107D9` |
| Entry point | `0x8262E960` | `0x8262E768` |
| Image base | `0x82000000` | `0x82000000` |
| Image size | 13,434,880 bytes | 13,434,880 bytes |
| Code base | `0x82020000` | `0x820E0000` |

The two builds are structurally almost identical. Address deltas are **not**
constant across the image. Observed deltas:

- `-0x1F0` in the `0x828xxxxx` thunk tables and around `0x828Axxxx`;
- `-0x168` in the prologue cinematic area (`0x823EB6xx`, `0x824B14xx`);
- `0` (identical addresses) in several regions, e.g. `0x8212F6xx`.

Never copy a PAL address into the USA config without checking its delta.

## Files added / changed

- `app/overrides_usa.toml` — hand-written USA codegen overrides: indirect-call
  targets found by running the game, plus the multi-entry thunk gaps that had to be
  subdivided every 8 bytes.
- `app/huecos_usa.toml` — gap list generated by `tools/huecos.py` for the USA XEX,
  curated the same way as the PAL `huecos.toml`.
- `app/nfsmw_manifest.toml` — `includes` now selects the USA files. To go back to
  PAL: `includes = ["overrides.toml", "huecos.toml"]`.
- `app/src/nfsmw_app.h` — the Black Edition flag is enabled for both regions: it is
  the same data address in every known version (`0x82A2CE04`, confirmed by Xenia's
  patch DB for all six hashes including NTSC-U).
- `launcher-linux/game_config.*` — English (US) locale defaults: language 1 /
  country 103 instead of the PAL Spain 5 / 31.
- `tools/parche_fpu.py` — SDK fix required by the USA build (see below).
- `tools/huecos_continuaciones.py` — computes the "continuation" entries of a gap
  list from a codegen log; kept for regenerating either region.

## The FP exception crash

The first USA builds died silently (no `[FATAL]`) with Windows event log exception
`0xc000008f` (float inexact) inside a generated function. Cause: the host MXCSR (FP
control word) can be left with the exception masks cleared on a guest thread, and
the next FP instruction then raises a hardware exception that the SEH filter does
not cover. `tools/parche_fpu.py` makes every write to MXCSR re-assert the masks.
`CONSTRUIR.bat` applies it and rebuilds the SDK.

## Building the USA version

1. Dump your own USA disc and extract `default.xex` (see `docs/01-extraccion-xex.md`).
2. Put it at `assets/game_root/default.xex` (or edit the manifest path).
3. Run `tools\bootstrap.ps1` once, then `CONSTRUIR.bat`.

The USA disc image used here contains only `default.xex`, `Movies\` and `NFS\`
(49 files, ~7.1 GB): the engine probes for `GLOBAL\`, `FRONTEND\`, `SOUND\`, etc.,
and those opens fail on this disc, which is expected and harmless.

## Known gaps

- **Black Edition flag**: the address is shared by all versions (`0x82A2CE04`, per
  Xenia's patch DB) and the patch applies, but unlocking it on a regular USA disc
  makes the game read Black Edition car data that is not on the disc (guest access
  violation reading guest `0x8`). The cvar now defaults to off; enable it only with
  Black Edition data.
- **Launcher language defaults**: the Linux launcher now defaults to English (US),
  language 1 / country 103. The Windows launcher already used the SDK defaults,
  which are also English (US).
- Missing `NtCreateFile` probes in the log (`GLOBAL\GAMEPLAY.LZC`, `SOUND\...`) are
  normal for this disc image.

================================================================================
  NFS: Most Wanted (Xbox 360)  -  Static recompilation
  Portable folder
================================================================================

HOW TO USE IT
-------------
  1. Copy your ISO into this same folder.
     If you name it  nfsmw.iso  that one will be chosen even if there are more.

  2. Double-click  NFS_Most_Wanted.exe

     That is THE LAUNCHER: it opens a window with the box art next to it where
     you choose ISO, resolution, scale, fullscreen or windowed, vsync,
     fps limit, video engine and graphics API. It remembers your choices
     for next time.

     If you prefer to go straight in, double-click  nfsmw.exe , which is the
     actual game: it takes the ISO it finds in the folder and the settings from
     nfsmw.toml.

     LANZADOR.bat opens the old version of that window, in PowerShell.
     It does the same thing and shares the settings; it is there just in case.

Nothing else. There is nothing to install, no parameters to pass, no ISO to
extract. The folder works wherever it is: C:\Juegos\, D:\, a USB stick, the
Desktop.


WHAT EACH FILE IS
-----------------
  NFS_Most_Wanted.exe      THE LAUNCHER. It carries the game icon because it
                           is what needs to be opened. It is not the game.
  nfsmw.exe                the game. See below for exactly what it is.
  rexruntime.dll           the SDK runtime: kernel, file system,
                           audio, input, window.
  rexgpu-xenos.dll         Xenos GPU emulation translated to Direct3D 12.
                           It loads at runtime, it is not linked.
  MSVCP140.dll             \
  MSVCP140_ATOMIC_WAIT.dll  |  Visual C++ runtime. They are here so you do not
  VCRUNTIME140.dll          |  have to install the Redistributable.
  VCRUNTIME140_1.dll       /
  LANZADOR.bat             the old options window, in PowerShell.
                           It does the same as NFS_Most_Wanted.exe and shares
                           the settings. It is here in case the launcher gives
                           trouble.
  lanzador.ps1             what LANZADOR.bat opens. Do not touch.
  COMPARAR_VIDEO.bat       compares the two video emulation engines.
                           Only needed if we ask you for a test.
  PROBAR.bat               startup test, in case the game does not open.
  matriz.ps1               what PROBAR.bat uses. Do not touch.
  nfsmw.toml               settings. The fast video engine is already selected.
  logs\                    created automatically when running.

The rest of what it needs -the UCRT, Direct3D 12, DXGI- is already part of
Windows 10 and 11.


WHAT THIS VERSION FIXES
-----------------------
THE AUDIO DIED AND THE GAME HUNG
  After leaving the garage after the prologue, the audio died within seconds,
  and trying to return to the menu left the game stuck.

  All the audio is handled by a single game thread: the same one feeds the
  decoder, consumes what comes out and mixes. When that thread entered to mix
  a voice that had just run out of data, it started waiting for audio that only
  the decoder could produce... a decoder it itself would have to feed as soon
  as it got out of there. And it never got out.

  The game has an emergency exit -when its read catches up with the write, it
  asks whether the buffer is still valid and, if told no, considers it
  finished- but in the jam it was one block away from catching up, so it never
  got to ask. Now it is given that signal when it has been spinning in vain for
  more than a quarter of a second.

  It may cost an audio glitch on that voice. In exchange for not hanging.

THE LOG WAS EATING THE CPU
  The "Too few processor cores" warning was written a thousand times per second
  on machines with few cores: 105 MB of log in a quarter of an hour, and the
  CPU it stole was exactly the one the audio needed. Now it appears once.

IF THERE IS NO COMPATIBLE GRAPHICS
  If none with Direct3D 12 feature level 11_0 is found, WARP -the software
  rasterizer- is tried before giving up. It is very slow, but it starts. And
  if there is no WARP either, a dialog box explains it, instead of the
  executable doing nothing when opened.


THIS IS NOT AN EMULATOR
-----------------------
The game's PowerPC code was translated to C++ and compiled as a native
x86-64 program. It runs directly on your CPU, interpreting nothing in real
time. Only the GPU is emulated, translating it to Direct3D 12.

Important consequence: the .exe is NOT a program that "loads" the game. It is
the game's own code, translated and compiled inside. Each copy is built from a
specific ISO.


SETTINGS
--------
It starts fine without touching anything. If you want to change something,
there are two ways.

By command line, which takes precedence over everything else:

    nfsmw.exe --resolution 1080p --resolution_scale 2

  --resolution WxH        window size and final image size.
                          Presets: 480p 540p 720p 900p 1080p 1440p 1800p 4k
  --resolution_scale N    the real INTERNAL resolution (1, 2, 3). Multiplies
                          the render targets. It costs squared: 2x is
                          four times the pixels.
  --fullscreen=false      start windowed.
  --game_data_root PATH   use another ISO or an extracted folder.
  --log_level debug       more detail in logs\

Or with a  nfsmw.toml  file next to the .exe, which the game reads on startup.
Note: game_data_root does NOT work there. The SDK resolves the paths before
reading the toml, so for that you have to use the command line.

It is called nfsmw.toml and not NFS_Most_Wanted.toml even if you rename the
.exe: that name comes from the project's internal name, not from the file.


IN-GAME
-------
  F3       fps and frame time
  F4       settings
  `        console

Xbox or PlayStation controller over USB or Bluetooth: works directly.
If it does not respond, the usual cause is Steam Input or DS4Windows capturing
it first.


IF SOMETHING FAILS
------------------
Everything ends up in  logs\ . The lines that matter carry [critical], [error]
or FATAL.

If "unregistered function at guest address 0x..." appears, WRITE DOWN THAT
ADDRESS. It is an indirect call target that static analysis cannot see, and it
only appears when the game walks that path. It is the most useful thing you can
report.

If Windows complains that a DLL is missing, say so with the exact name: it
means the folder was assembled incomplete.

If you see [desatasco] lines, that is the audio fix kicking in. One every now
and then is normal and harmless. If they come in droves, say so: it means the
audio thread is tight on time on that machine and there is something else to
look at.
